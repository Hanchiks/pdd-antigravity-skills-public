# Экспериментальный кандидат pdd.py 02D1F

Дата работы: **13 ноября 2026**. Этот кандидат подготовлен в изолированной копии и не был установлен в рабочий каталог. Он добавляет проверку привязки устройства перед чтением экрана и дерева интерфейса и учитывает вертикальные координаты при проверке активного поля.

Для независимой проверки из корня репозитория используйте `python3 scripts/verify_versions.py`: рабочая версия и этот кандидат запускаются раздельно, вывод указывает конкретный файл. Кандидат **не принят** в `runtime/pdd.py`; документированного обоснования для продвижения нет. Для проверки как замены используйте только отдельную копию `runtime/`, перенеся туда этот `pdd.py` и тест в `tests/`. Рабочая версия в `runtime/pdd.py` сохранена. Проверки опасных действий, контекста карточки и избранного в этом кандидате совпадают с рабочей версией; отличия остаются только в проверке привязки устройства перед чтениями и в учёте вертикальных координат активного поля. Не считать кандидата проверенным на реальном телефоне; ранее отдельные safety-oracles для другой ветки не запускались. Ограничение на реальные жесты из правил остаётся в силе.

## Этап 1, часть D (изменения синхронны с рабочей версией)

В этой копии, как и в `runtime/pdd.py`, добавлены межпроцессная блокировка устройства по серийному номеру перед действиями (порядок: устройство → состояние), проверка фактической геометрии перед действием с инвалидацией кеша при расхождении, строгая сверка размера скриншота и разделение результата на `command_sent`, `state_confirmed` и `unknown`. Отличия кандидата от рабочей версии по-прежнему только два: проверка привязки устройства перед чтениями и учёт вертикальных координат активного поля. Блокировки проверены офлайн на Linux; поведение `msvcrt` на Windows и реальная геометрия/ориентация телефона остаются к проверке. Блокировка не управляет прямым `adb` или другим инструментом, который её игнорирует.

## Этап 1, часть E (изменения синхронны с рабочей версией)

В кандидате, как и в `runtime/pdd.py`: `text` не выводит введённый текст, чувствительные вызовы `run_adb` редактируют argv в ошибках таймаута, `--clear` без ADBKeyboard явно отклоняется, а с ADBKeyboard подтверждается повторным чтением поля; установленный ADBKeyboard сверяется по SHA-256 `base.apk` (`unknown` — явное предупреждение), broadcast ограничен пакетом; `push-photo` использует уникальные имена и не перезаписывает существующие файлы намеренно (атомарность `adb push` не гарантируется); `clean` различает найденное/удалённое/ошибки, не следует по симлинкам и возвращает `status` `dry_run`/`ok`/`partial`/`failed`. Отличия кандидата от рабочей версии остаются прежними: проверка привязки устройства перед чтениями и вертикальные координаты активного поля. Проверка на реальном телефоне, включая перехват broadcast и видимость argv в системных журналах, не выполнялась.
