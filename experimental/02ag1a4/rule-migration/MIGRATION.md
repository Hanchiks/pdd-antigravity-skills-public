# Миграция глобального правила: до → после

## 1. Что мигрируется

Активное правило `~/.gemini/config/rules/AGENTS.md` — устаревший PDD-only документ (один H1, 34 строки, без посторонних разделов). Оно конфликтует с принятой политикой 02C2:

- ссылается на Gemini 3.8 Flash;
- содержит старую логику цены и порядка действий;
- не содержит запретов 02A–02C2 (включая `直接拼成`, `tap --force`, групповые покупки);
- не запрещает реальные жесты до приёмки.

## 2. Проверенная разметка

| | было | станет |
|---|---|---|
| файл | `AGENTS.md` (8563 байта) | тот же путь |
| структура | один H1 + 34 строки | `PDD-SECTION.md` (7927 байт) |
| посторонние правила | нет | сохраняются (их нет) |
| PDD-блок | 1 | 1 |
| приватные данные | нет (проверено) | нет |

Копия в пакете — `rule-migration/old-rule.redacted.md`: **синтетическая заглушка** без пользовательских данных, не извлечение из живого правила. Живой файл в архив не включён и не восстанавливается из патчей.

## 3. Детерминированная трансформация

```powershell
python rule-migration\migrate_rule.py `
  --current rule-migration\old-rule.redacted.md `
  --target antigravity\rules\PDD-SECTION.md `
  --output rule-migration\merged-candidate.md
```

Правила:

1. Старый файл обязан быть чисто PDD-документом. Признак постороннего раздела — H2 с темами вне PDD; тогда код `rule_merge_unverified` и **никакой** автоматической установки.
2. Целевой текст обязан содержать обязательные контроли и не содержать устаревших маркеров (с учётом отрицаний: «копии `scratch\pdd-operator` не существует» — допустимо).
3. Результат заменяет содержимое целиком, а не дописывается блоком: два конкурирующих PDD-раздела недопустимы.
4. PDD-заголовок в результате встречается ровно один раз.
5. Выходной путь не может совпадать с текущим правилом.

Результат `merged-candidate.md` побайтово равен `antigravity/rules/PDD-SECTION.md`; это проверяет `verify/overlay_check.py` (`merged_candidate_conflict`).

## 4. Проверка конфликтов после миграции

- Нет `Gemini 3.8`, `scratch\pdd-operator` (кроме отрицания), «все жесты защищены», `--operator-dir`, `PDD_OPERATOR_DIR`.
- Есть все обязательные контроли и раздел «Жесты: запрет до приёмки».
- Нет разрешения нажимать `直接拼成` ради цены (смысловая проверка, не по словам).
- Количество PDD-заголовков равно 1.

## 5. Резервная копия и откат

См. `ROLLBACK.md`: копируется только заменяемый `AGENTS.md`, хеш сверяется до и после, откат восстанавливает файл из копии и сверяет `expected_before`. Удаление каталогов не выполняется.

## 6. Ограничения

- Живое правило не проверялось на наличие посторонних разделов за пределами шаблона; если фактический файл отличается от копии, миграция обязана остановиться по хешу.
- Если Antigravity поддерживает подключение отдельных rule-файлов, замена общего `AGENTS.md` не требуется — тогда используется прямое подключение `PDD-SECTION.md`; это отдельное решение, не автоматизированное здесь.

## 7. Гейт точного фингерпринта (02AG1P2)

Замена разрешена только когда SHA-256 текущего файла входит в явно одобренный набор:

- по умолчанию одобрен ровно один хеш — синтетическая фикстура `rule-migration/old-rule.redacted.md` (`e52f4447…`); она не является живым правилом и не содержит его строк;
- для живого файла хеш передаётся вручную: `--approved-sha256 <hex>` после проверки содержимого и сохранения копии;
- любой посторонний H1/H2 или абзац меняет хеш → `rule_merge_unverified`, файл не изменяется и ничего не удаляется;
- фикстура **не доказывает** ничего о живом правиле: перед заменой оператор обязан сверить живой файл глазами, снять свежий SHA-256 и сделать проверенную независимую копию.

Дополнительно проверяется структура: ровно один H1 с PDD-темой, отсутствие посторонних разделов, наличие обязательных контролей в целевом тексте.

## 8. Ограничение вывода (02AG1P3)

Генератор пишет только внутри staging-каталога (`--staging-root`, по умолчанию корень пакета). Путь, содержащий `.gemini/config` или `.codex`, отклоняется как живой, даже если он отличается от `--current`. Живое правило этим инструментом не изменяется.

## 9. Фикстура 02AG1A2

`old-rule.redacted.md` в этом пакете — синтетическая заглушка (SHA-256 `e52f4447…`), а не живое правило. Живой файл не распространяется. Гейт точного фингерпринта для реальной миграции требует свежего SHA-256 живого правила, переданного вручную через `--approved-sha256`, и проверенной независимой копии.
